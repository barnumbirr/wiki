## Upgrades

### Memory

QNAP's TS-873A comes with 8GB of DDR4-2666 non ECC memory as standard. This is a
Kingston product marketed as QNAP RAM under part number `RAM-8GDR4T0-SO-2666`.

Upgraded to 64GB of DDR4-2666 ECC Unbuffered memory from Kingston with part
number KSM26SED8/32ME.

- [Memory Datasheet](https://www.kingston.com/dataSheets/KSM26SED8_32ME.pdf)

### System SSD

QNAP just like Synology devices have an internal flash memory chip. This is
where the default QuTS/QTS/DSM operating system and configuration are stored.
Whichever drive (SSD or HDD) that you initially setup your QNAP with will house
not only your apps but also QNAP configuration itself, etc...

QNAP's TS-873A comes with two M.2 2280 PCIe Gen3 x1 slots that were populated
with Samsung 980 500GB SSDs, part number `MZ-V8V500BW`.

- [Datasheet](https://s3.ap-northeast-2.amazonaws.com/global.semi.static/Samsung_NVMe_SSD_980_Data_Sheet_Rev.1.1.pdf)

### Video

!!! danger "Read this before blaming the drivers"
    NVIDIA® drivers are **not** broken under QuTS hero h6.0.1. Three separate
    issues can make them look broken; each has a distinct signature and a
    one-line fix, see
    [Troubleshooting the NVIDIA driver stack](#troubleshooting-the-nvidia-driver-stack).
    Verified working on `QuTS hero h6.0.1.3550` with `NvKernelDriver
    6.0.1.3550` and `NVIDIA GPU Driver 6.2.2.1106` (driver `575.64.05`,
    CUDA 12.9).

PNY NVIDIA® Quadro® P1000, mainly used for Plex Media Server
Hardware-Accelerated Streaming.

- [Datasheet (NVIDIA)](https://www.nvidia.com/content/dam/en-zz/Solutions/design-visualization/productspage/quadro/quadro-desktop/quadro-pascal-p1000-data-sheet-us-nv-704475-r1.pdf)
- [Datasheet (PNY)](https://www.pny.com/file%20library/company/support/product%20brochures/nvidia%20quadro/english/pny-nvidia-quadro-p1000-v2.pdf)

Two packages are required; they complement each other and are **not**
QTS/QuTS alternatives:

- `NvKernelDriver`: the kernel modules. Pinned to the **exact firmware
  build** (its `Build` date must match the firmware build date), so a
  matching version is needed again after every firmware update.
- `NVIDIA GPU Driver` (`NVIDIA_GPU_DRV`): the userspace half; libraries,
  `nvidia-smi` and creation of the `/dev/nvidia*` device nodes. Its init
  script refuses to start until `NvKernelDriver` is registered with
  `Status = complete` (the gate also accepts `queue`) in
  `/etc/config/qpkg.conf`.

After installing the card into the TS-873A, QTS/QuTS should automatically
install `NvKernelDriver` at boot. This can fail silently when the network
isn't up yet (see Troubleshooting below). In that case, download the package
matching your exact firmware version from the QNAP website and install it
manually **through App Center**. Avoid `sh package.qpkg` from the CLI: the
self-extracting wrapper aborts on a benign gzip warning caused by the
digital signature appended to the archive, and a manual `qinstall.sh` run
does not write the `Status = complete` registry key that `NVIDIA_GPU_DRV`
requires (failure mode 3 below).

Under `Control Panel > System > Hardware > Hardware Resources`, allocate
the graphics card to OS/NAS use ("QTS mode") instead of Virtualization
Station passthrough. The change only takes effect at the next reboot; until
then `vfio-pci` keeps ownership of the PCI device (failure mode 2 below).

#### Troubleshooting the NVIDIA driver stack

The three known failure modes have distinct signatures:

**1. CLI installation aborts with `tar: Child returned status 2`**

```bash
gzip: stdin: decompression OK, trailing garbage ignored
/bin/tar: Child returned status 2
/bin/tar: Exiting with failure status due to previous errors
```

The `.qpkg` carries a digital signature appended after the embedded gzip
stream. `gzip` decompresses the payload successfully (valid CRC) but exits
with status `2` to signal the "trailing garbage" warning; `tar` propagates
the non-zero child status and the wrapper's `[ $? = 0 ] || exit 1` guard
aborts before ever running `qinstall.sh` — even though extraction into
`<pool>/.qpkg.local/.tmp` completed in full (the failure path performs no
cleanup). Prefer App Center. To finish a CLI install anyway:

```bash
[~] # cd /share/ZFS1_DATA/.qpkg.local/.tmp
[~] # sh ./qinstall.sh
[~] # setcfg NvKernelDriver Status complete -f /etc/config/qpkg.conf
[~] # setcfg NvKernelDriver Status complete -f /etc/config.local/qpkg.conf
```

**2. `insmod: can't insert nvidia.ko: No such device`**

`dmesg` shows `NVRM: The NVIDIA probe routine was not called for 1
device(s)` / `NVRM: No NVIDIA devices probed`; the flood of `unknown symbol`
errors for `nvidia-modeset`/`nvidia-drm`/`nvidia-uvm` that follows is
cascade noise (they depend on symbols exported by `nvidia.ko`). The card is
bound to `vfio-pci` because it is allocated to VM passthrough:

```bash
[~] # ls -l /sys/bus/pci/devices/0000:01:00.0/driver
lrwxrwxrwx 1 admin administrators 0 [...] driver -> ../../../../bus/pci/drivers/vfio-pci/
```

Re-allocate the card in `Hardware Resources` (see above) and reboot.

**3. Kernel modules loaded but no `/dev/nvidia*`; `NVIDIA GPU Driver` stuck
on `Stopped` and re-disabling itself**

`NVIDIA_GPU_DRV.sh start` polls `getcfg NvKernelDriver Status -f
/etc/config/qpkg.conf` for up to 120 seconds expecting `complete` (or
`queue`). That key
is only written by the App Center installation flow; after a manual
`qinstall.sh` install it is missing, so the script times out, sets
`NVIDIA_GPU_DRV Enable = FALSE` **itself** and exits — making every
subsequent start attempt (App Center toggle, `qpkg_service start`) fail
silently. Fix:

```bash
[~] # setcfg NvKernelDriver Status complete -f /etc/config/qpkg.conf
[~] # setcfg NvKernelDriver Status complete -f /etc/config.local/qpkg.conf
[~] # setcfg NVIDIA_GPU_DRV Enable TRUE -f /etc/config/qpkg.conf
[~] # /etc/init.d/NVIDIA_GPU_DRV.sh start
```

!!! note
    The Event Log error `[Hardware Status] Failed to automatically install
    the driver: NvKernelDriver` can reappear on any boot: the downloader in
    `/etc/rcS.d/S61nv_kernel_drv` runs early in the boot sequence and,
    despite a built-in internet-reachability check, gives up within seconds
    when the network stack isn't ready yet. It is cosmetic as long as a
    firmware-matched
    `NvKernelDriver` is installed locally — the package's own init script
    loads the kernel modules later in boot.

#### Force HW video encoding/decoding in Plex Media Server

With current Plex Media Server and `NVIDIA GPU Driver` >= 6.2.2.x this
workaround is no longer needed: the Plex QPKG detects that it was installed
before `NVIDIA_GPU_DRV` and waits for the NVIDIA stack on startup. If Plex
came up before the driver did (typically right after installing the driver
for the first time), a single restart is enough:

```bash
[~] # /share/ZFS2_DATA/.qpkg/PlexMediaServer/plex.sh restart
Stopping Plex Media Server...
PlexMediaServer installed before NVIDIA_GPU_DRV. Plex will attempt to wait for Nvidia to start
Starting Plex Media Server...
```

??? "Legacy fix (driver 515 era)"

    In some cases and for seemingly unknown reasons, even when setting the
    graphics card to `QTS mode` in the QTS/QuTS interface as explained
    above, Plex Media Server won't use it for hardware video
    encoding/decoding.

    To force Plex to use the installed graphics card, make sure the card is
    properly detected:

    ```bash
    [~] # gpuhal_app -l
    1:NVIDIA Corporation:GP107GL [Quadro P1000]:external:7
    ```

    Get graphics card information, such as mode and installed drivers:

    ```bash
    [~] # gpuhal_app -s 1
    active_status=2,real_status=2,driverqpkg=NVIDIA_GPU_DRV,driver_installed=1,in_used=none,transcode=1,display=1,pcie_slot=1,pcie_vp=1,va_type=none
    ```

    Check that the card has a device file and a render node under
    `/dev/dri/`:

    ```bash
    [~] # ls -la /dev/dri/
    total 0
    drwxr-xr-x  2 admin administrators       80 2022-02-18 11:22 ./
    drwxr-xr-x 17 admin administrators    21380 2022-02-25 13:53 ../
    crw-------  1 admin administrators 226,   0 2022-02-18 11:22 card0
    crw-------  1 admin administrators 226, 128 2022-02-18 11:22 renderD128
    ```

    Add the following to your `Preferences.xml` file and restart Plex Media
    Server.

    ```bash
    [~] # nano /share/ZFS530_DATA/.qpkg/PlexMediaServer/Library/Plex\ Media\ Server/Preferences.xml
    [...] HardwareDevicePath="/dev/dri/renderD128"
    ```

    You should now be able to use hardware video encoding/decoding.

## Configuration

### Persistant crontab

The normal method of editing your crontab does not work on QNAP NAS' as it does
not persist after a reboot. To make crontab changes persistant, do the
following:

```bash
[~] # nano /etc/config/crontab
[~] # crontab /etc/config/crontab
[~] # /etc/init.d/crond.sh restart
```

## Usage

### Fix `nvidia-smi` PATH

With `NVIDIA GPU Driver` >= 6.2.2.x no PATH or `LD_LIBRARY_PATH` fix is
needed for `nvidia-smi`: both the `usr/lib/bin/` copy and the old
`usr/bin/` entry point run bare (verified with `env -u LD_LIBRARY_PATH`).
The `usr/lib/` tree is populated by the package's start script from the
shipped `usr/nvidia/` payload (copies for the NVIDIA binaries and
libraries, symlinks for the libva/libdrm shims):

??? "Legacy behaviour (driver 515 era)"

    When trying to invoke the nvidia-smi utility from the command-line, the
    command fails with the following error:

    ```bash
    [~] # /share/ZFS530_DATA/.qpkg/NVIDIA_GPU_DRV/usr/bin/nvidia-smi
    NVIDIA-SMI couldn't find libnvidia-ml.so library in your system. Please make sure that the NVIDIA Display Driver is properly installed and present in your system.
    Please also try adding directory that contains libnvidia-ml.so to your system PATH.
    ```

    To fix this, add the necessary directory to your PATH as follows:

    ```bash
    [~] # export LD_LIBRARY_PATH="/share/ZFS530_DATA/.qpkg/NVIDIA_GPU_DRV/usr/nvidia.u18.04$LD_LIBRARY_PATH"
    [~] # /share/ZFS530_DATA/.qpkg/NVIDIA_GPU_DRV/usr/bin/nvidia-smi
    ```

    Only `/share/ZFS530_DATA/.qpkg/NVIDIA_GPU_DRV/usr/nvidia.u18.04` can be
    added to `LD_LIBRARY_PATH`.

    ```bash
    [~] # find / -path /share/ZFS19_DATA/ -prune -o -name "libnvidia-ml.so" -print
    /share/ZFS530_DATA/.qpkg/NVIDIA_GPU_DRV/usr/lib/libnvidia-ml.so
    /share/ZFS530_DATA/.qpkg/NVIDIA_GPU_DRV/usr/nvidia/libnvidia-ml.so
    /share/ZFS530_DATA/.qpkg/NVIDIA_GPU_DRV/usr/nvidia.u18.04/libnvidia-ml.so
    /share/ZFS530_DATA/.qpkg/NVIDIA_GPU_DRV/cuda-11.7/targets/x86_64-linux/lib/stubs/libnvidia-ml.so
    [~] #
    ```

    Using any other directory listed above allows for `nvidia-smi` to work
    as expected but results in PMS failing to start with the following
    error:

    ```bash
    [~] # /share/ZFS530_DATA/.qpkg/PlexMediaServer/plex.sh restart
    Plex Media Server hasn't been enabled or started...
    Starting Plex Media Server...
    [~] # Error relocating ./Plex Media Server: drmGetDevices2: symbol not found
    ```

    The PATH issue was reported to QNAP on November 23rd 2021 but was
    discarded with the following reply:

    > The [NVIDIA GPU Driver] qpkg is used for NAS web UI to display NVidia
    GPU card status, so it can be assigned to HD Station, Linux Station, or
    Hardware Transcoding. This qpkg doesn't provide the library path in the
    environment by default.

### Manually setting GPU fan speed

!!! warning
    Verified working headless on `NVIDIA GPU Driver` 6.2.2.1106 (driver
    `575.64.05`): setting `GPUTargetFanSpeed=100` physically spun the fan
    up from 34% duty (94% observed in `nvidia-smi` five seconds in) and
    `GPUFanControlState=0` handed control back to automatic. Invoked bare,
    `nvidia-settings` fails with `error while loading shared libraries:
    libXext.so.6`; the `LD_LIBRARY_PATH` export below is still required
    (the X client libraries live in `usr/applib/` and `usr/syslib/`). The
    `Failed to connect to Mir` / `Unable to init server` noise is harmless.

```bash
[~] # export LD_LIBRARY_PATH=$LD_LIBRARY_PATH:/share/ZFS530_DATA/.qpkg/NVIDIA_GPU_DRV/usr/applib/:/share/ZFS530_DATA/.qpkg/NVIDIA_GPU_DRV/usr/lib/:/share/ZFS530_DATA/.qpkg/NVIDIA_GPU_DRV/usr/syslib/
[~] # /share/ZFS530_DATA/.qpkg/NVIDIA_GPU_DRV/usr/bin/nvidia-settings --display :0 -a GPUFanControlState=1 -a GPUTargetFanSpeed=100
Failed to connect to Mir: Failed to connect to server socket: No such file or directory

  Attribute 'GPUFanControlState' ([gpu:0]) assigned value 1.

  Attribute 'GPUTargetFanSpeed' ([fan:0]) assigned value 100.

[~] # /share/ZFS530_DATA/.qpkg/NVIDIA_GPU_DRV/usr/bin/nvidia-settings --display :0 -a GPUFanControlState=0

[~] #
```
